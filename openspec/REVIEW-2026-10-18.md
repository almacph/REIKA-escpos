## Main findings

- The current health check sends Init every 30 seconds; it tests a write, not paper/cover readiness. Failed idle checks do not reconnect. The health proposal replaces this with non-destructive capability-aware checks and serialized recovery.
- Reconnection keeps the old device alive while opening a new one; manual IN endpoints are guessed. Both are addressed with explicit ownership, descriptor validation, and stale-generation handling.
- REIKA's current thermal contract requires legacy Italic to be ignored, while the unstaged desktop code enables it. The proposed resolution retains parsing compatibility but removes italic output. All initial unstaged changes are classified in the command proposal's [evidence](changes/align-reika-print-command-contract/evidence.md).
- Latest stable versions were checked against crates.io. egui/eframe 0.29.1 → 0.37.0 requires a compiler upgrade (latest package MSRV 1.95 versus local 1.92). Tokio 1.38.0 → 1.53.3, Warp 0.3.7 → 0.4.3, escpos 0.17.0 → 0.20.1 are candidates; rusb 0.9.4 remains current. See the full [stack review](changes/modernize-desktop-platform/stack-review.md) and registry snapshot. Candidates have not been compiled or hardware-tested.
- WinUSB is the default fresh-install target, not libusb0 plus WinUSB together. A device-specific signed package and elevated selected-device helper can replace normal manual Zadig setup. Production signing and actual interface matching remain release inputs. See [driver design](changes/add-windows-setup-and-watchdog/design.md).
- Further separate decisions: local API trust/private CA enrollment, durable job IDs/cancellation/idempotency, and signed update/rollback UX. These are documented recommendations, not bundled implementation promises.

## Validation

All four proposal packages pass `openspec validate <id> --strict --no-interactive`. The pre-existing base specs `escpos-commands` and `usb-driver` fail for missing Purpose sections; repair is scheduled without changing the existing user-edited base spec during this review. No Rust changes or hardware tests were performed. cargo-audit is not installed, so a full vulnerability audit remains open; age alone is not evidence of a vulnerability.
